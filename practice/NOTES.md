## 第 1 课 · 可复现的基线（W1）

### 一句话

让"跑两次结果一样"从**感觉**变成**能自动验证的事实**。

### 1. 随机性有三个源头，但它们共用一条种子流

一个训练脚本里的随机性来自三处：

| 来源 | 代码位置 | 影响 |
|---|---|---|
| 数据生成 | `torch.randn(N, 1)` | 数据集本身 |
| 权重初始化 | `nn.Linear(...)` 的内部初始化 | 模型起点 |
| 数据打乱 | `DataLoader(..., shuffle=True)` | 每轮的 batch 顺序 |

关键理解：**它们不是三个独立的随机源，而是从同一个全局生成器里连续取数**。所以在最前面调用一次 `torch.manual_seed(seed)`，后面所有地方都被钉死了——不需要在每个地方都写一次。

顺序很重要：`manual_seed` 必须放在**任何**随机调用之前。放在造数据之后，前面那步就不受控。

### 2. `torch.manual_seed` 也管 GPU

很多人以为 GPU 上要额外写 `torch.cuda.manual_seed_all()`。不需要——`torch.manual_seed()` 内部会一并设置所有设备的种子。（多卡场景另说。）

### 3. 验收要用 8 位小数，不是 4 位

第一课最容易犯的错：靠眼睛看 4 位小数判断"两次一样"。

- 4 位是给人看的，会被四舍五入掩盖差异
- 8 位是给程序看的，能暴露浮点层面的漂移
- 真正的验收标准是**逐位一致**，不是"看着差不多"

### 4. CONFIG 的边界：什么该进，什么不该进

判断标准只有一条：**你会不会去调它。**

| 该进 CONFIG | 不该进 |
|---|---|
| lr、batch、epochs、hidden_dim | `device`（环境属性，换机器本来就该变） |
| `noise_std`（会想试噪声大点） | `x ∈ [-3, 3]`（数据集固有定义，基本不会调） |
| `data_weight`（会想试信号强弱） | 代码逻辑本身 |

灰色地带靠自己判断，**但判断时要能说出理由**。

### 5. 抽 CONFIG 时最容易漏的地方

**不是主逻辑里的参数，而是验证/展示代码里的同一个数。**

踩过的具体例子：`data_weight` 已经抽进 CONFIG 了，但最后画对照表那行还写着 `+ 0.5 * x`。这是个**真 bug**——改 CONFIG 后，训练数据变了而"真值"没变，你会去调一个根本没问题的地方。

**教训**：抽完之后用搜索功能找一遍那个数字，确认没有漏网的。

### 6. 重构的验收标准：行为不变

改结构（抽 CONFIG、改函数签名、拆分文件）之后，**输出必须逐位相同**。

这次的做法：重构前后各跑一次，对比 `train_loss` / `val_loss` 的 8 位小数。一致 = 重构成功；不一致 = 你改到了逻辑。

这条习惯的价值：以后你改动别人的代码、或者优化自己的训练脚本时，它是唯一能证明"我没搞坏"的手段。

### 7. 遗留问题（下次补）

- [ ] 打印太多会污染日志，以后要换成 `logging` 或写文件
- [ ] `EPOCHS = CONFIG['epochs']` 这层中间变量要不要留？还没想清楚
- [ ] 还没试过：改 `noise_std` 会怎么影响最终 val_loss？（这正好是第一次"真调参"）

## 第 2 课 · 过拟合诊断与数据增强（W3）

### 一句话

**准确率高低不是重点，"训练集和测试集的差值"才是模型健康度。**

### 1. 三分类诊断（所有训练问题的第一个岔路口）

| 训练准确率 | 测试准确率 | 差值 | 诊断 | 处方 |
|---|---|---|---|---|
| 低 | 低 | 小 | 欠拟合 | 多训、加宽加深、降 lr |
| 高 | 低 | **大** | 过拟合 | 数据增强、正则、早停 |
| 高 | 高 | 小 | 健康 | —— |

关键是**必须同时有两个数**。只有一个测试准确率，你根本判断不出问题出在哪。

### 2. 过拟合的真正信号：不是 test 下降，而是 train 涨 + test 平

我的实测数据（无增强，20 轮）：

| | epoch 12 | epoch 20 |
|---|---|---|
| train | 87.27% | **95.10%**（+7.8） |
| test | 75.06% | **74.97%**（−0.1） |

测试准确率几乎没动，但训练准确率涨了 7.8 个点——**模型在背答案，不是在学特征**。

如果只盯着 test 看，会误以为"训练已经到头了"；实际上模型还在疯狂过拟合，只是测试集看不出增益。

### 3. 数据增强：制造"同一张图的不同版本"

**原理**：一张猫的图，平移几像素、左右翻一下，它还是猫。把这些变体喂给模型，等于凭空扩充了数据集，逼它学**对这些变换不变的特征**，而不是记像素位置。

**CIFAR-10 常用的两种**：

```python
train_transform = transforms.Compose([
    transforms.RandomCrop(32, padding=4),   # 先补到 40×40，再随机裁回 32×32 → 位置变化
    transforms.RandomHorizontalFlip(),      # 50% 概率左右翻转 → 朝向变化
    transforms.ToTensor(),
])

test_transform = transforms.ToTensor()      # 测试集保持原样
```

**两条铁律**：

1. **只用于训练集**。测试集要随机增强的话，每次评估结果都不一样，没法比较。
2. **几何变换要放在 `ToTensor()` 之前**。RandomCrop / HFlip 作用于 PIL 图像；放到 ToTensor 之后就变成在张量上操作，语义和速度都不一样。

### 4. 认知陷阱：加增强后训练准确率会掉，这是好事

| | 无增强 | +增强 |
|---|---|---|
| train | 95.10% | **79.50%**（掉了 15.6） |
| test | 74.97% | **78.81%**（涨了 3.84） |
| gap | 20.1 | **0.7** |

训练任务被故意变难了，所以训练准确率下降是**预期行为**。判断进步只能看 `test`。

### 5. 下一步该继续训练还是改模型？

看 **test 曲线**：

- **还在涨** → 继续训练（我的实验 #5，ep20 还在上升，说明没收敛）
- **平台了，但 train 还在涨** → 改正则/增强/早停
- **两个都不动** → 加模型容量

所以"训练多少轮"不该拍脑袋，看曲线决定。

### 6. 这一课踩到的两个工程坑

**a. 抽函数参数后，函数体里的旧名字没改**

```python
def evaluate(loader):
    for xb, yb in test_loader:   # ← 参数加了，循环没改
```

这个 bug 不报错，只会让 `evaluate(train_loader)` 悄悄在测试集上评估，然后把结果当训练准确率打印。**两个数字会一模一样，还以为是好事。**

教训：给函数加参数后，回头搜一遍函数体里所有旧名字。

**b. Windows 上 `num_workers > 0` 必须配 `__main__` 保护**

否则子进程会重新执行整个脚本，脚本又开始建 DataLoader、又开子进程……无限递归直到卡死。

```python
def main():
    ...

if __name__ == "__main__":
    main()
```

### 7. 遗留问题（下次补）

- [ ] 加增强后训练变慢：`num_workers=0` 让预处理和 GPU 串行，GPU 在等 CPU
- [ ] `transforms.ToTensor()` 只做了 /255，还没试过 `Normalize`（用 CIFAR 的均值方差）
- [ ] 还没试：weight decay、cosine 学习率调度、早停
- [ ] 训练集准确率还是偏低（79.5%），模型容量可能不够——下一步可以加到 4 层卷积

## 第 3 课 · BatchNorm 与学习率调度（W4）

### 一句话

**BN 解决收敛速度，调度解决震荡。只加 BN 不加调度，收益会被震荡吃掉。**

### 1. BN 加在哪、参数写多少

```python
nn.Conv2d(3, 32, 3, padding=1),
nn.BatchNorm2d(32),      # ← 32 必须等于前一个 Conv 的 out_channels
nn.ReLU(),
```

**顺序不能换**：`Conv → BN → ReLU`。

因为 ReLU 会把所有负数砍成 0，如果特征本身整体偏负，ReLU 之后一大片全是 0，BN 再标准化也救不回来。先 BN 把分布拉到以 0 为中心，ReLU 才能正常激活一半。

**参数写错的报错**：`running_mean should contain 32 elements not 3`——这里的数字是**通道数**，不是图片尺寸、不是类别数。

### 2. BN 有"训练时"和"推理时"两套行为

| 阶段 | 用谁的均值方差 |
|---|---|
| `model.train()` | 当前 batch 的，同时**累计**一份全局 running stats |
| `model.eval()` | 用累计好的那份，不看当前 batch |

所以 `model.train()` / `model.eval()` 从"少一点点"变成了"必须写对"。忘了 `eval()`，评估结果会随 batch 组成跳动。

### 3. 实测：BN 单独用是"快但抖"

40 轮、同样 lr=1e-3、同样数据增强，只差有没有 BN：

| 区间 | 无 BN | 加 BN |
|---|---|---|
| 1–10 均值 | 64.97 | **70.32**（+5.35） |
| 31–40 均值 | 80.77 | 81.15（+0.38） |
| 峰值 | 81.33 | **83.29**（+1.96） |
| 末 10 轮 std | 0.48 | **1.99**（×4） |

**结论**：BN 让前期收敛快很多，峰值也抬高了 2 个点，但**末段平均只涨 0.38——中间 1.6 个点被震荡吃掉了**。

### 4. 怎么区分"过拟合"和"优化震荡"（关键判据）

| 现象 | train | test | 诊断 |
|---|---|---|---|
| train 涨、test 跌 | ↑ | ↓ | **过拟合**，gap 扩大 |
| **train 和 test 同步跌** | ↓ | ↓ | **优化震荡**，权重在曲面上来回弹 |

实测数据：

```
ep23 → 79.84      ep24 → 70.14      train 也同步掉到 71.70
ep35 → 82.01      ep36 → 77.11      train 也同步掉到 79.06
```

两个一起掉，就不是模型"学过头了"，而是**优化器在乱跳**。

**为什么会这样**：BN 改变了损失曲面的尺度，等效于把学习率放大了。BN 论文里"可以用更大 lr"的前提是**配合调度**，不是无脑用。

### 5. 余弦退火：把 lr 慢慢降到 0

```python
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(
    optimizer, T_max=CONFIG["epochs"]
)

for epoch in range(1, EPOCHS + 1):
    ...训练...
    ...评估...
    scheduler.step()          # ← 每个 epoch 末尾调一次
```

**位置很关键**：`scheduler.step()` 在 **epoch 层**调用（每轮一次），不要放进 batch 循环（那是 `OneCycleLR` 之类的用法）。

原理：前期保持大 lr 快速下降，后期 lr → 0，模型"慢慢落进"谷底而不是在谷底来回蹦。

**验证是否生效**：把 lr 打印出来，40 轮里应该从 `0.001000` 平滑衰减到 `0.000000`。

### 6. 阶段 3 完整成绩单（四个改进，同数据同模型）

```
74.97%  基线（无增强无正则）
78.81%  + 数据增强         (+3.84)
81.15%  + BatchNorm        (+2.34)
84.34%  + 余弦学习率调度    (+3.19)
                          ────────
                          +9.37 点
```

四个改动没有一个是"调参玄学"，每一个都有明确的机制解释。

### 7. 遗留问题

- [ ] 84.34% 之后，末 10 轮标准差 0.41，已经收敛——下一个瓶颈大概率是**模型容量**，该换结构了
- [ ] 没试过：`Normalize`（用 CIFAR 均值方差）、weight decay、label smoothing
- [ ] `Dropout(0.3)` 一直包含在基线里，从没单独消融过，不知道它到底贡献了多少

## 第 4 课 · 残差连接与论文精读（W7）

### 一句话

残差连接改造的是**优化难度**，不是表达能力——它让"好解"变得"可达"。

### 1. 退化问题 ≠ 过拟合

| | 训练误差 | 测试误差 | 原因 |
|---|---|---|---|
| 过拟合 | 很低 | 高 | 记答案 |
| **退化** | **也很高** | 高 | **优化器训不动** |

**判据**：看到"训练误差更高"，就同时否掉了过拟合和容量不足两个解释。

### 2. 论文的核心论证（值得背下来）

```
① 深层网络如果多出来的层全学成恒等映射 → 训练误差至少该和浅层一样好
② 但实测更深反而更差
③ 所以：好解是存在的，只是优化器走不到
④ 定位病因 = 优化问题，不是表达问题
```

第 ① 步是整个论证的地基。**"至少不该更差"这个下界，把问题从"能力不足"逼成了"优化困难"。**

### 3. 解法：把"学恒等"变成"学零"

```
原来的层：  y = F(x)          要恒等 → F 得学成"x"（难）
残差块：    y = F(x) + x      要恒等 → F ≈ 0 就行（容易）
```

### 4. BasicBlock 的四个设计决定

| 写法 | 原因 |
|---|---|
| `padding=1` + `kernel=3` | 卷积后尺寸不变，是能相加的前提 |
| `bias=False` | 后面接 BN，bias 会被减均值吃掉，纯属浪费 |
| `out + x` 在**第二个 BN 之后、ReLU 之前** | 先加再激活；先激活再加可能得到负数，残差意义被削弱 |
| 每个 stage 只有**第一个块**带 stride 和 1×1 投影 | 变形只在入口做一次，stage 内部保持同构 |

### 5. shortcut 的两种形式（论文 Table 3）

| 方案 | 形状变化时 | 参数量 | ResNet-34 top-1 |
|---|---|---|---|
| A 零填充 | 补零到目标通道 | 0 | 25.03 |
| B **1×1 投影** | 1×1 卷积映射 | 有 | **24.52** |
| C 全投影 | 所有 shortcut 都用 1×1 | 最多 | 略好，未采用 |

**A 和 B 只差 0.51 个点** → 论文结论："projection shortcuts are **not essential**"。

**真正起作用的是"有捷径"，不是"捷径怎么对齐形状"。**

⚠️ 注意：形状一变，"纯恒等"物理上就不存在了（64 通道加不到 128 通道上）。所以 A 是"零填充 + 恒等"，不是纯恒等。

### 6. ⚠️ 最重要的辨析：梯度高速路不是原文的解释

我之前讲"残差给梯度修了高速路，解决梯度消失"——**这是业界流行说法，论文明确排除了它**。

论文 Section 4.1 原文：

> "this optimization difficulty is **unlikely** to be caused by vanishing gradients. These plain networks are trained with BN... **So neither forward nor backward signals vanish.**"

论文自己的猜想是 **"exponentially low convergence rates"**（收敛速度指数级变慢），并承认原因待研究。

| 解释 | 来源 | 和原文一致吗 |
|---|---|---|
| 恒等映射容易学（学零） | Section 3.1 | ✅ 论文核心论证 |
| 梯度高速路 | 业界流行 | ❌ 论文明确排除 |
| 2ⁿ 条路径的隐式集成 | Veit et al. 2016 | 📖 后续工作 |

**教训：一手论文永远优先于二手转述——包括我给你讲的。**

### 7. 读论文的七步论证链（通用模板）

| 步骤 | ResNet 里对应 |
|---|---|
| ① 观察现象 | Figure 1：56 层训练误差 > 20 层 |
| ② 排除其他解释 | 训练误差更高 → 不是过拟合；层更多 → 不是容量不足 |
| ③ 理论推导 | 深层网络至少该和浅层一样好 |
| ④ 定位病因 | 恒等映射难学 → 优化问题 |
| ⑤ 提出方法 | `y = F(x) + x` |
| ⑥ 验证方法 | Table 2：34 层 ResNet vs plain-34，降 3.5 点 |
| ⑦ 消融实验 | Table 3：三种 shortcut 对比 |

**任何论文都可以先找这七步。缺哪步，就是它最容易被攻击的地方。**

三个阅读警惕点：
1. **摘要里的数字要看清条件**（ResNet 的 3.57% 是 ensemble，不是单模型）
2. **消融实验比主结果重要**（主结果告诉你"它能行"，消融告诉你"为什么能行"）
3. **作者的解释和流行的解释可能不一致**（见第 6 点）

### 8. 一个反直觉的发现

论文 Table 2：**18 层时 plain 和 ResNet 几乎一样**（27.94 vs 27.88）。

原因：网络"不够深"时普通网络照样能训好，**残差只在深到训不动时才显出价值**。

→ 这解释了我在 SmallCNN（3 层卷积）上的经历：加不加残差无所谓；一旦堆到 34 层就是生死差别。

### 9. 实测成绩（ResNet-18 on CIFAR-10）

| 区间 | train | test | gap |
|---|---|---|---|
| 1–10 | 76.08% | 74.72% | 1.36 |
| 21–30 | 98.12% | 91.31% | 6.81 |
| 31–40 | 99.75% | **92.47%** | **7.28** |

- 比 SmallCNN 的 84.34% **高 8.13 点**
- 但 gap 从 2.6 涨到 7.28 → **容量够了，开始过拟合**
- 每轮 34s，40 轮共 23.4 分钟

## 第 5 课 · 正则化的量级与"对症"（W8）

### 一句话

**两个独立的判断：① 这个手段生效了吗？② 这个手段治得了我的病吗？** 我这次只验证了 ①。

### 1. weight_decay 的数值本身没有意义

AdamW 每步做两件独立的事：

```
梯度更新：  w ← w − lr · m/√v        量级 ≈ lr
权重衰减：  w ← w · (1 − lr·λ)        量级 ≈ lr·λ·|w|
```

`m/√v` 被归一化到约 ±1，所以：

**有效强度 = λ · |w|**（衰减相对梯度的比例）

### 2. 总效果看累积

```
w_n ≈ w_0 · e^{−n·lr·λ}
```

**决定性的是 `n · lr · λ` 这个乘积**，不是 λ 单独。

我的配置：`n = 391 × 40 = 15,640 步，lr = 1e-3`

| λ | n·lr·λ | 累计衰减 |
|---|---|---|
| 1e-4 | 0.0016 | 0.16% |
| 5e-4 | 0.0078 | 0.78% |
| 1e-3 | 0.0156 | 1.55% |
| **1e-2** | **0.078（含余弦折半）** | **7.7%** |
| 5e-2 | 0.39 | 32% |

### 3. ⚠️ 余弦调度会让 weight decay 打折

这是我自己算错的地方：以为 `lr = 1e-3` 恒定，算出 14.5%。

**实际上余弦退火让平均 lr 只有峰值的 51%**，所以 `Σ(lr × steps) = 8.02` 而不是 15.64，真实衰减 **7.7%**。

**教训**：讲"累积量"时不能拿初始 lr 去乘步数，要算 lr 的实际积分。

### 4. 为什么 1e-4 和 1e-2 都没效果

两次实验的结果（末 10 轮均值）：

| 配置 | train | test | gap |
|---|---|---|---|
| Adam, wd=0 | 99.75% | 92.47% | 7.28 |
| AdamW, wd=1e-4 | 99.77% | 92.59% | 7.18 |
| AdamW, wd=1e-2 | 99.74% | 92.49% | 7.25 |

**三组几乎完全一样。** 7.7% 的权重收缩，没能让 train 准确率动一个千分位。

三个原因：

1. **深度网络的记忆不靠"大权重"**——是靠大量小权重分布式编码，L2 范数惩罚压不住
2. **14% / 7.7% 的收缩面对 11M 参数的容量还是太弱**（5 万张图 vs 1117 万参数，每个参数只对应 0.004 张图）
3. **gap 7 点对 CIFAR-10 + ResNet-18 是正常值**，不是病态过拟合，没什么"需要治"的

### 5. 最硬的对照证据

| 手段 | 效果 |
|---|---|
| RandomCrop + HFlip | **+3.84 点** |
| weight decay（0 → 1e-2） | **+0.02 点** |

差 200 倍。**病根是"数据不够"，对症的药就是"让数据看起来更多"（数据增强）**，而不是"限制权重"。

### 6. 可以迁移到所有超参的规则

**① 正则化的强度是相对量**
任何正则项（L2、Dropout、Label Smoothing）都要问"它和主梯度相比多大"，而不是"这个数字大不大"。

**② 超参量级依赖优化器**

| 优化器 | wd 常用范围 |
|---|---|
| SGD | 1e-4 ~ 5e-4 |
| Adam | 1e-4 ~ 1e-3 |
| **AdamW** | **1e-2 ~ 5e-2** |

**③ 抄别人的超参时，先算它的"累积量"，再判断是否可比**

### 7. 最大的收获：机制发生 ≠ 机制对症

我算出了"权重确实被缩小了 7.7%"，这是真的（用零梯度的 AdamW 验证过）。但我把它当成了"过拟合会好转"的证据——**这两个是独立命题**。

**"我做了 A"不等于"A 解决了 B"。** 做实验最容易犯的错就是这个。

正确的流程应该是：

```
① 结果不符预期 → 先查代码有没有 bug（排除实现错误）
② 验证机制真的执行了（确认 A 发生了）
③ 才判断 A 是否对症（这时才轮到质疑假设）
```

## 第 6 课 · 消融实验：怎么证明"是它"（W8）

### 一句话

调参问的是"**怎么调更好**"，消融问的是"**到底是不是它**"。前者优化分数，后者建立因果。

### 1. 消融和调参，差在一个字：只动一个

| | 调参 | 消融 |
|---|---|---|
| 动什么 | 超参（lr、wd、epochs） | **结构/机制**（shortcut、BN、增强） |
| 对照要求 | 尽量一致 | **其余全部锁死**：参数量、轮数、调度、增强 |
| 目的 | 刷分 | 回答"这个机制买到了什么" |

这次为了做消融，先把实验 #9 原样重跑了一遍（#14）：92.47% vs 92.53%，**差 0.06**。这一步不能省——**没有等价性验证，消融的两组差异里就掺着"这几天改代码改出来的差"**。

### 2. 拆 shortcut 有三种写法，选"最不改变别的东西"的那个

```python
# 原版
if in_ch != out_ch or stride != 1:
    self.shortcut = nn.Sequential(
        nn.Conv2d(in_ch, out_ch, 1, stride, bias=False), nn.BatchNorm2d(out_ch))
else:
    self.shortcut = nn.Identity()

# 消融版（--plain 为真时）
if plain:
    self.shortcut = None          # 连 Identity 都不要
```

前向时：

```python
if self.shortcut is None:
    out = self.relu(out)          # 直连，但保留 BN 后的 ReLU
```

**为什么不是"把 shortcut 换成 Identity"？** 因为 Identity 就等于原版了，消融等于没做。**为什么不是"删掉整个 conv2 + relu"？** 那会连非线性都改掉，变量从一个变成两个。`shortcut=None` 只删掉**加性通路**，其余原封不动——这才是单变量。

### 3. 三个读数，看哪个

| 读数 | ResNet-18 | plain-18 | 我怎么读 |
|---|---|---|---|
| 末轮 **train** | 99.88% | **98.91%** | **最关键的一行** |
| 前 10 轮 test | 74.60% | 64.20% | 早期差距 **−10.4** |
| 末 10 轮 test | 92.53% | 90.48% | 最终差距 **−2.05** |

**train 也掉了，这一句就排除了两个假设：**

- 若是**容量不足** → test 低，但 train 应该差不多（拟合得动只是泛化差）
- 若是**过拟合** → train 应该**更高**，test 低

两个都不是，只剩一个：**它根本没拟合好 → 优化问题**。这和论文 Fig.1 的论证是同一个形状。

**而早期差距（10.4）是最终差距（2.05）的 5 倍。** 如果 shortcut 的作用是"增加表达力"，差距应该体现在最终上限上；现在它主要体现在**前 10 轮**——说明它买的是**优化速度**，不是容量。

plain 的峰值出现在 **ep39**（最后一轮），ResNet 在 ep33 就平了。**plain 不是到顶了，是还没爬上去。**

### 4. 一个副产品：参数量核对前，必须先确认"哪个版本"

写 LeNet 时我照 `nn.Conv2d(..., bias=True)` 的老结构算，目标是 **61,706**。结果跑出来是 **61,848**，差 **142**。

查下来发现我写的是 `bias=False` + `BatchNorm2d`——是 ResNet 那套现代写法的惯性。差额正好是：

```
6 + 16 + 120 = 142
（三个卷积层各自的输出通道数）
```

因为：

| 写法 | 每层多几份参数 |
|---|---|
| `Conv2d(bias=True)`，无 BN | 卷积核 + **1 × 输出通道** |
| `Conv2d(bias=False)` + `BN` | 卷积核 + **2 × 输出通道**（BN 的 weight 和 bias） |

**这不是 bug，是两个版本。** 1998 年的 LeNet-5 没有 BN（BN 是 2015 年的），所以原版是 61,706。

**教训：报"参数量对不上"之前，先问"我在核对哪个版本"。** 数字差异必须能被**逐层解释**，解释不了才是 bug。142 这个数能被 6+16+120 精确解释，所以它是版本差异；解释不了的那种差异，才是真问题。

### 5. 我没做到的事（要写下来）

退化的定义是：**层数增加，训练误差反而上升**（plain-34 比 plain-18 差）。我做的是**同深度**下有/无 shortcut——证明了 shortcut 有优化增益，方向一致，但**不是同一个实验**。

## 第 7 课 · LeNet-5 与数据管道（W1）

### 一句话

训练循环只写一次，数据管道每次都要重写；而**变换的一致性**比模型结构更容易出错。

### 1. 参数账：钱都在最后一层卷积

`61,848 = C1 150 + BN 12 + C3 2,400 + BN 32 + C5 48,000 + BN 240 + F6 10,164 + out 850`

- **C5 一层就占 78%**
- C5 + F6 + out = 59,134，占 **95.6%**

卷积层很便宜（权重共享），全连接层才是参数大户。这也解释了 AlexNet 为什么 96% 参数在 FC。

### 2. 六个 bug，归成三类

| 类型 | bug | 症状 |
|---|---|---|
| 漏一步 | 训练集缺 `ToTensor` | 直接崩：`TypeError: pic should be Tensor or ndarray` |
| 漏一步 | 测试集缺 `Normalize` | **不报错**，静默丢精度 |
| 命名 | ckpt 用 `resnet18_` 前缀 | 覆盖掉 ResNet 的存档 |
| 时机 | csv 写盘放在训练循环**之后** | 跑完 15 轮才崩 |

**最贵的是"时机"类**：代码写错了，但错误发生在几十分钟之后。所以"能跑通"不等于"写对了"——**先跑 1 轮冒烟测试**。

**"互补的残缺"**：训练集缺 `ToTensor`（崩）、测试集缺 `Normalize`（不崩）。它们缺的不是同一样东西，别以为"两边都少一个"就叫对称。

### 3. 变换一致性规则（背下来）

| 变换 | 训练集 | 测试集 |
|---|:---:|:---:|
| `ToTensor` | ✅ | ✅ |
| `Normalize` | ✅ | ✅ |
| `Resize` | ✅ | ✅ |
| `RandomCrop` / `HFlip` / `Erasing` / `CutMix` / `MixUp` | ✅ | ❌ |
| `CenterCrop` | ❌ | ✅ |

**判据：随机性只属于训练集，测试必须确定性。**

正例：前 15 组 CIFAR 实验训练和测试**都只有 `ToTensor`**——缺 Normalize，但两边都缺，所以自洽、不是 bug，只是少了个该有的步骤（已记 P5）。

### 4. `padding=2` 不能乱改

LeNet 原版输入是 32×32，MNIST 只有 28×28，所以 conv1 用 `padding=2` 补到 32。

**后果**：如果在数据管道加 `RandomCrop(32, pad=4)`，输入变成 32×32，尺寸链 32→16→8→2，`Flatten` 出 **480** 而不是 120，`F6` 的 `in_features` 就错了。

**结构的 padding 和数据管道的尺寸变换是耦合的，改一边必须重算另一边。**

### 5. `Normalize` 的两个数从哪来

`(0.1307,) (0.3081,)` 是 MNIST 全体训练像素的均值和标准差；CIFAR 是 `(0.4914,0.4822,0.4465) / (0.2023,0.1994,0.2010)`。

单元素**必须写逗号**：`(0.1307,)` 才是 tuple，`0.1307` 是 float。

### 6. 结果与"饱和"判据

15 轮，test **99.29%**（峰值 99.30%），4.5 s/轮。

**判据：ep12 起 test 在 99.26–99.30 之间随机游走、没有趋势 → 饱和，不是在学。**

`train 100%` vs `test 99.29%` 有 0.71 的 gap，但在 MNIST 上无害——**判断 gap 要不要治，看 test 有没有随 gap 一起掉**，这里没掉。

### 7. 为什么 99.29% 不能和 ResNet 的 92.53% 比

**Fashion-MNIST 反例**：同样 28×28、单通道、10 类、6 万张，LeNet 只有约 **92%**。

所以难度来自**语义**，不是**尺寸**。

> 准确率 = f(模型, 数据集, 训练预算)，**不是模型的属性**。

### 8. 记录口径：last vs best

`results.csv` 一直记的是**最后一轮**的 `test_acc`，而 checkpoint 里存的是 `best_acc`。

| 实验 | best | last | 差 |
|---|---:|---:|---:|
| LeNet | 99.30 | 99.29 | 0.01 |
| P1（100 轮） | 94.22 | 94.13 | **0.09** |

0.09 足以改变"加某增强涨了 0.05"这种结论。**A1 没解决这个问题，只加了成本三列。**

## 第 8 课 · 成本画像：参数量、MACs、延迟（A1）

### 一句话

准确率不是模型的属性，是"模型 × 数据 × 预算"的联合属性；**只有把成本也量化，比较才有意义**。

### 1. 三个指标的口径

| 指标 | 定义 | 坑 |
|---|---|---|
| `params` | `sum(p.numel() for p in model.parameters())` | 只算可训练参数；BN 的 `running_mean/var` 是 buffer，不算 |
| `MACs` | 乘加次数 | **1 MAC = 2 FLOPs**，论文里两者常混用 |
| `infer_ms` | 单张前向延迟中位数 | bs=1 时被 kernel 启动开销主导 |

### 2. thop 的原理就四行

它做的就是**注册 `forward_hook` + 按层类型套公式累加**：

```
Conv2d : out.numel() × (in_channels / groups) × kh × kw
Linear : in_features × out.numel()
Norm   : out.numel()
Pool/激活/Flatten : 0（只有比较和取数，没有乘加）
```

**这次没装成 thop**（pip 卡了 6 分钟），于是自己写了 40 行，逻辑就是上面四行。

**教训**：这类"统计工具"内部都极简单，卡住时自己实现往往比等下载快，而且顺便看懂了它。

### 3. 命名撞标准库（真实踩坑）

把脚本命名为 `tools\profile.py`，直接报错：

```
AttributeError: module 'profile' has no attribute 'run'
(consider renaming ... since it has the same name as the standard
 library module named 'profile')
```

**原因**：Python 启动时把脚本所在目录放进 `sys.path[0]`，你的 `profile.py` 抢在标准库前面被 import，而 `cProfile` 内部要 `import profile`。

**黑名单**：`profile` / `csv` / `json` / `random` / `types` / `email` / `io` / `code` / `statistics`。

### 4. bs=1 的延迟不可信

同一份代码连跑三次：

| 模型 | 第 1 次 | 第 2 次 | 第 3 次 |
|---|---:|---:|---:|
| ResNet18 | 3.73 ms | 3.13 ms | 3.14 ms |
| Plain18 | 2.85 ms | 2.86 ms | 3.25 ms |

**单张推理的地板约 0.3–0.5 ms**（kernel 启动开销），低于这个量级的差异全是噪声。

更严重的是：**FLOPs 低不代表快**。大 kernel、depthwise、逐元素 add 都可能 FLOPs 很低但带宽受限。要测真实吞吐得用大 batch（bs=128）看 **images/s**。

## 第 9 课 · 退化问题与深度消融（W8）

### 一句话

**"更深"不是免费的。没有 shortcut，加深会让网络连训练集都拟合不了——这不是过拟合，是优化失败。**

### 1. 退化（degradation）的精确定义

> 网络层数增加，**训练误差反而上升**。

注意是**训练误差**，不是测试误差。这个区别是整个论证的命门：

| 现象 | train | test | gap | 说明 |
|---|---|---|---|---|
| 过拟合 | ↑ 高 | ↓ 低 | ↑ 大 | 记住训练集但没泛化 |
| 容量不足 | ↑ 高 | ↓ 低 | 中 | 模型太小装不下 |
| **退化** | **↓ 低** | ↓ 低 | **↓ 小** | **连训练集都学不会** |

**只有退化这一行是 train 和 gap 同时变差。** 看到 train 掉了，就不能说过拟合。

### 2. 实测数据（40 轮，同数据/同增强/同优化器）

| 深度 | plain | ResNet | gap |
|---|---|---|---|
| 18 | 90.48% | 92.53% | +2.05 |
| 34 | **83.69%** | **93.30%** | **+9.61** |
| 18→34 | **−6.79** | **+0.77** | **×4.7** |

**plain-34 的 train 只有 85.72%，gap 1.68** —— gap 比 ResNet-34 的 4.09 还小。这一行单独就能排除"过拟合"和"容量不足"两个假设。

### 3. 为什么 18 层看不出来，34 层才看得出来

第 6 课做过 #14/#15（18 层的 ResNet vs plain），只能证明"**shortcut 在同深度下改善可优化性**"（+2.05）。

**但那不是退化。** 退化的定义要求**两条曲线反向分离**：

```
精度
 ↑
 │  ResNet:  92.53 → 93.30    ↑ +0.77
 │  plain :  90.48 → 83.69    ↓ −6.79
 └────────────────────────→ 深度  18    34
```

- 18 层时两条线**平行**（都有 +2.05 的固定差）→ 只能说明 shortcut 有用
- 34 层时两条线**反向张开** → 才能说明"深度本身有害，残差能解"

**所以消融实验的设计里，"选几个档位"和"只改一个变量"一样重要。** 两档是最低要求，论文用了四档（20/32/44/56）。

### 4. 首轮就分出胜负：伤害从哪来

| | 首轮 test |
|---|---|
| ResNet-34 | 47.95% |
| plain-34 | 20.60% |

**差 2.3 倍，19.89% 的 train 甚至接近随机猜（10%）**。后面 39 轮差距一路扩大，但**起点就已经差了一倍**。

这说明深度造成的伤害是**一开始就有**的，不是在训练过程中慢慢累积的——梯度从第一次反向传播就已经流不回浅层了。

### 5. 一个反直觉的发现（论文没讲）

**40 轮预算下，ResNet-34（93.30%）比 ResNet-18（92.53%）只高 0.77 点，但参数 ×1.90、时间 ×1.83。**

而从 #18 的 93.57 看，**ResNet-34 甚至比同配置的 ResNet-18 低 0.27 点**。

> **加深不需要不花钱，而且预算不足时加深是亏的。**

ResNet 论文在 CIFAR-10 上用 **200 轮**；我们只用 40 轮。34 层的峰值出现在**最后一轮**（还在涨），说明它根本没跑满。

**这条对做工程决策比复现论文更重要**：真实场景里，"加深度"之前先问"训练预算够不够"。**加大模型 ≠ 更强，加大模型 + 不够的训练 = 更差。**

### 6. 埋过的坑：基线选错会得出反向结论

我两次犯同一个错：

1. 第一次（Normalize）：拿 `#14`（`erase=0`）当基线，实际 `#17` 用了 `erase=0.5`，**两个变量一起动**
2. 第二次（ResNet-34）：用 `#14` 的 92.60 当基线算增量 → 得出 "+0.9" 的预测；正确的是 `#18` 的 **93.57** → 实际 **−0.27**

**两次都是同一个病：拿不同配置的数当基线。**

> **写任何"提升了 X 点"之前，先确认两个数来自同一条增强管线、同一个轮数、同一个优化器。**
> 工具：`tools\diff_config.py`，直接读两个 checkpoint 里存的 config 逐项对比。

### 7. 复现论文，复现的是什么

| | 论文 Fig.1 | 本实验 |
|---|---|---|
| 轮数 | 200 | **40** |
| 档位 | 20 / 32 / 44 / 56 | **18 / 34** |
| plain | 训练误差随深度**上升** | train 98.91 → **85.72** |
| ResNet | 训练误差随深度**下降** | train 99.88 → **97.63** |
| 结论 | 退化是优化问题 | ✅ 同向 |

**绝对数字一个都没对上**（我们 40 轮、单卡、还加了增强），**但因果链对上了**。

> **复现 = 复刻因果，不是复刻数字。** 数字对不上是正常的，因果方向对不上才是问题。

## 第 10 课 · 注意力机制：从加权平均到 Transformer Block（W2）

> 代码：`07_attention.py`（单头）→ `08_mha.py`（多头）→ `09_transformer_block.py`（完整 block）→ `10_pos_and_mask.py`（位置编码与掩码）
> 演示：`tools\demo_attention.py`（八步推导）

### 1. 它解决什么问题

RNN 有两个病：

| 病 | 具体表现 |
|---|---|
| 不能并行 | 第 t 步必须等第 t−1 步算完，1000 个时间步 = 1000 次串行 |
| 长程依赖会断 | 第 1 个词的信息传到第 1000 个词，要穿过 999 次乘法 → 梯度路径长度 = L |

**attention 的解法一句话：把路径长度从 L 变成 1。**

第 1000 个词要拿第 1 个词的信息，直接连一条边，不经过中间任何东西。

> **历史纠正**：attention **最初不是网络层，是 2014 年机器翻译的对齐机制**（Bahdanau）。
> 当时的痛点是"encoder 把整句压成一个固定向量"的瓶颈——解码第 5 个法文词时需要回头看英文原句的第 2 个词。
> 2015 Luong 整理出 `dot / general / concat` 三种打分函数，QKV 的形式才成型。
> 2017 *Attention Is All You Need* 做的是**把 RNN 删掉，只留 attention + FFN**——这是第二步，不是发明。

### 2. 前置知识（比想象中少）

**必须会**：向量点积、softmax、加权平均、矩阵乘法视为"批量线性组合"。
**不需要**：反向传播推导、位置编码、多头、RNN。

**注意**：attention 的数学门槛**比 ResNet 低**。它 2017 年能赢很大程度是因为**比 LSTM 简单**（LSTM 有三个门 + 细胞状态，attention 只有一个公式）。

### 3. 从"手写权重"到"自己算权重"

**第 0 步：目标是加权平均**

```python
out = 0.50*猫 + 0.30*狗 + 0.20*追     # 权重和为 1
```

问题：**这 0.50 / 0.30 / 0.20 谁写的？** 人写的就不叫学习。

**第 1 步：用点积当相似度**

```
q = [1, 0, 0, 0]        # 猫
k_猫 = [1, 0, 0, 0]     # → 1.000
k_狗 = [0.9, 0.15, 0, 0]# → 0.900
k_球 = [0, 0, 1, 0]     # → 0.000
```

点积大 = 方向接近 = 相似。**这就是打分的来源。**

**第 2 步：softmax 变成"和为 1 的百分比"**

```
softmax([1.000, 0.900, 0, 0]) = [0.379, 0.343, 0.139, 0.139]
```

为什么必须用 exp：
- 非负（点积可以是负数，概率不行）
- 保序（单调，最大的还是最大）
- 可微（能训练）

**第 3 步：加权求和 —— 到这里 attention 已经完整了**

```python
out = 0.379*v_猫 + 0.343*v_狗 + 0.139*v_追 + 0.139*v_球
```

**但注意：这一版没有任何可学习参数。** 权重不是参数，是**输入算出来的中间结果**。

**第 4 步：加 Q/K/V 三个投影，才有参数**

```python
q = x @ Wq    # (B,L,d) @ (d,d) → (B,L,d)
k = x @ Wk
v = x @ Wv
```

参数量 `3(d²+d)`，与序列长度 L 无关。

### 4. 检索类比（理解 QKV 的钥匙）

| 检索系统 | attention |
|---|---|
| 搜索框里输入的关键词 | **Q**（Query，我要找什么） |
| 每篇文章的标题 / 标签 | **K**（Key，我是什么） |
| 文章的正文 | **V**（Value，我能提供什么内容） |
| 关键词和标题的匹配度 | `Q·K` |
| 归一化成百分比 | softmax |
| 按比例混合各篇正文 | `权重 @ V` |

**关键：Q 和 K 只用于"匹配"，用完就丢；V 才是实际被取用的内容。**

### 5. 完整公式与形状

```python
scores = q @ k.transpose(-2, -1) / math.sqrt(d)   # (B,L,L)
w      = torch.softmax(scores, dim=-1)            # (B,L,L) 每行和为 1
out    = w @ v                                    # (B,L,d)
```

**形状口诀**：

> **进去 `(B,L,d)`，出来 `(B,L,d)`，中间鼓一个 `(B,L,L)`。**

三个易踩的点：

| 坑 | 为什么错 |
|---|---|
| `k.T` | `.T` 反转**所有**维度，`(2,5,8) → (8,5,2)`。要用 `transpose(-2,-1)` 只换最后两维 |
| `softmax(dim=-2)` | 能跑、loss 照降，但语义完全错——变成"每列和为 1"。用「列和 ≠ 1」可以证明 `dim=-1` 没写错 |
| 忘除 `√d` | d 大时 softmax 饱和，梯度 `p(1-p) ≈ 0` |

### 6. 为什么除 √d —— 实测数据

q·k 是 d 个随机数的乘积之和，**方差正比于 d**：

| d | q·k 的 std（实测） | 理论 √d | 不缩放时最大权重 | 除以 √d 后 |
|---|---|---|---|---|
| 8 | 3.36 | 2.83 | 0.319 | 0.023 |
| 64 | 7.55 | 8.00 | 0.647 | 0.015 |
| 512 | **23.10** | 22.63 | **0.912** | 0.014 |

d=512 时最大权重 0.912 → 梯度 `p(1-p) = 0.08` 已经很小，再大就归零。**除 √d 是让方差回到 1 左右。**

### 7. 和卷积/全连接的本质区别

| | 卷积 / 全连接 | attention |
|---|---|---|
| 权重谁决定 | **学出来的固定核** | **输入实时算出** |
| 输入长度 | 固定 | **可变** |
| 有非线性吗 | 有 | **没有（纯线性的加权求和）** |
| 参数量 | 与输入大小有关 | `3d²`，**与 L 无关** |
| 计算量 | O(L·k²) | **O(L²)** |

三条推论：

1. **attention 本身是线性的**，堆 10 层等于一个大线性变换 → **非线性必须由 FFN 提供**
2. **O(L²) 是所有效率方向论文的起点**（L 从 512 到 8192，计算量涨 256 倍）
3. **没有位置概念**（打乱 token 顺序，输出跟着重排）→ 必须加位置编码

### 8. 多头：分的是"相似度定义"，不是"数据片段"

**误解**：d=16、h=4 时，以为 head0 只看输入的第 1~4 维。

**实际**：改任意一个输入维，head0 的 q 都会变（因为 `Wq` 是 `Linear(16,16)`，每个输出维依赖全部 16 个输入维）。

**分组发生在 Wq 之后，不在之前。**

| 误解 | 实际 |
|---|---|
| 每个头看到输入的一部分 | 每个头看到**全 16 维混合后的 4 个投影** |
| 头之间是不同数据片段 | 头之间是**同一输入的不同的相似度定义** |
| 被隔离的是信息 | 被隔离的只有 **softmax 的归一化范围** |

**分析师类比**：4 个分析师看同一份财报（都读了全本），各自提炼 4 个数字的摘要再各自排序，最后老板（W_O）合并。**分的是摘要角度，不是原文页码。**

**W_O（输出投影）为什么必须有**——两个理由，第二个才关键：

1. 表面：多头要汇总。但**拼接本身零交流**（12 段 `(B,L,64)` 拼成 `(B,L,768)`），W_O 是唯一能混合 12 个头的地方
2. 根本：`w @ v` 的结果住在 **V 的向量空间**里，下一层要用的是**残差流那个统一空间**，W_O 负责翻译
   → **和 ResNet 在 shortcut 上做 1×1 投影是同一类活**

> **踩过的坑**：验收时差 72 个参数（`288 vs 216`）= `8×8+8` = 一个 `Linear(8,8)`，那就是 `out_proj`。
> **标准 attention 是四个矩阵不是三个**。

### 9. LayerNorm 与 block 结构

```python
# 整个 block 就 6 行
def forward(self, x, attn_mask=None):
    x = x + self.attn(self.ln1(x), attn_mask=attn_mask)   # 子层 1
    x = x + self.ffn(self.ln2(x))                          # 子层 2
    return x
```

**精髓在两行里**：送进子层的是 `self.ln1(x)`，参与相加的是**原样的 x**。
写成 `x = self.ln1(x) + ...` 就退回 Post-LN 了。

**LN 公式**：`y = (x - mean(x)) / sqrt(var(x)+eps) * γ + β`
**统计轴只沿最后一维 d，每个 token 独立算一组。**

| | BN | LN |
|---|---|---|
| 统计轴 | `(N,H,W)` | `(d)` |
| 用别的样本吗 | 用 | **不用** |
| train/eval 一致吗 | 不一致 | **完全一致** |
| buffer | 有 running_mean/var | 无 |
| batch=1 | 崩 | 正常 |
| 序列长度可变 | 不行 | **可以** |

**实测**：改同 batch 里另一个 token 的值 +10 → `LN 前后差 = 0.000000`，`BN 前后差 = 1.533740`。

**必须用 LN 的三个理由**：
1. 序列长度不固定，padding 的 0 会污染 BN 统计量
2. 大模型单卡 batch 只有 1~4，BN 统计噪声巨大
3. **自回归生成会泄露未来**（BN 跨整序列算统计量 = 训练作弊）

一句话：**BN 假设"样本之间可以互相看"，LN 假设"每个 token 只能看自己"。**

**Pre-LN vs Post-LN**：

- Pre-LN 残差通路是**纯恒等**，梯度一路直通，**不需要 warmup**
- Post-LN 残差加法后还有 LN，反向会乘上和方差相关的因子，层数一深连乘 → 必须 warmup

**实测：权重完全相同下，两种接法输出差 1.4966，比输入 std（0.9601）还大** → 是两个完全不同的函数，不是实现细节。

> 这条规律在 ResNet 上见过一次：原版 `relu(F(x)+x)` vs Pre-activation `x+F(relu(x))`。
> **想让梯度直通，就不要往残差通路上放任何东西——ReLU 不行，LN 也不行。**

### 10. FFN：block 唯一的非线性来源

```python
ffn = nn.Sequential(
    nn.Linear(d, 4*d), nn.GELU(), nn.Linear(4*d, d)
)
```

- **逐位置**：第 5 个 token 过 FFN 时看不到第 4/6 个
- 二分法：**attention = token mixing，FFN = channel mixing**（MLP-Mixer 的依据）
- **4 倍是纯经验值**（原论文在 512/1024/2048/4096 里试出 4）
- 参数量约为 attention 的 **2 倍**（d=768 时 4,722,432 vs 2,362,368）
- **GELU 优于 ReLU**：平滑、负半轴有非零梯度，避免 dying ReLU

**为什么必须有**：attention 对 V 是线性的，堆 10 层等价于一个大线性变换。**FFN 是 block 唯一的非线性来源。**

### 11. 一个反直觉的读数：block 初始化时近似恒等映射

实测（d=32, h=4）：

```
LN1 后   std = 1.0013
attn 输出 std = 0.1713   ← 只有输入的 18%
相加后   std = 0.9613     ≈ 输入 0.9601
```

**随机初始化下，每个 block 几乎什么都没做。** 这就是为什么能堆 96 层——每一层开局都是"什么都不改"，训练只需要学"该改哪一点"。

### 12. 位置编码与因果掩码

**attention 对顺序完全无感（置换等变）**：`dog bites man` 和 `man bites dog` 对它是同一个输入。

**验证方法**（这个设计很关键）：
不比 `out_perm` vs `out`（当然不等），而是比 **「打乱后跑」vs「跑完打乱」**。

```
无位置编码:   最大差 5.96e-08  → True（置换等变）
加位置编码:   最大差 0.1018    → False（顺序有影响了）
```

**正弦编码的相似度不单调**（实测）：

| 距离 | 1 | 3 | 4 | 5 | 12 |
|---|---|---|---|---|---|
| 余弦相似度 | 0.9571 | 0.767 | **0.7288** | **0.7361** | 0.7155 |

距离 5 的相似度 > 距离 4；距离 12 ≈ 距离 3。

**因为它编码的是"位置指纹"而不是"绝对距离"**，多频率叠加会回弹。
→ **这就是 RoPE 之所以赢的原因：它让点积直接携带相对距离。**

**因果掩码**：

```python
mask = torch.triu(torch.ones(L, L, dtype=torch.bool), diagonal=1)
```

- **`diagonal=1` 不含对角线**（每个 token 必须能看见自己）
- 写成 `diagonal=0` 会让位置 0 整行 `-inf` → **softmax 得 NaN**
- `masked_fill` **必须在 softmax 之前**（`softmax(-inf) = 0/Σ = 0`）

**因果性的操作定义**（比肉眼看矩阵可靠）：改最后一个 token，看前面的位置有没有变。

## 第 11 课 · 手写 mini GPT（W2）

> 代码：`practice\11_mini_gpt.py`（206 行）
> 验证：`tools\verify_minigpt.py`（四层）、`tools\inspect_minigpt.py`（拆开看参数）、`tools\show_temperature.py`（温度）

### 1. 五块积木

```
token id (B,T)
  ↓ tok_emb + pos_emb
(B,T,d)
  ↓ × N 个 TransformerBlock
(B,T,d)
  ↓ ln_f
(B,T,d)
  ↓ head (Linear d→V)
(B,T,V) = logits
  ↓ 与 y 算交叉熵
```

**输入输出形状全程不变 `(B,T,d)`** —— 所以能堆任意多层。

### 2. `nn.Embedding` 就是查表

它等价于 `one-hot(65) @ W(65,128)`，但**只做一次索引，不做乘法**。

| | `tok_emb` | `pos_emb` |
|---|---|---|
| 查什么 | **字是谁**（id 0~64） | **第几个位置**（0~63） |
| 形状 | `(65, 128)` | `(64, 128)` |
| 参数量 | 8,320 | 8,192 |

**为什么要两个**：token 相同的字在不同位置应该有不同表示（"的"在句首和句尾作用不同）。

**为什么是相加不是拼接**：

```
tok_emb(30) = [-0.0761, 0.0644, -0.0423, -0.0559]
pos_emb( 0) = [-0.0201, -0.0329, -0.0243, -0.0392]
相加       = [-0.0963,  0.0315, -0.0666, -0.0951]   ✓ 手算一致
```

- 拼接会让维度翻倍（参数 ×4），还要人为划分"前 128 内容 / 后 128 位置"
- 相加虽然混在一起，但下游 4 层线性变换能自己拆开
- **不要替模型做它自己能学的事**

### 3. 权重绑定（weight tying）

```python
self.head.weight = self.tok_emb.weight    # 注意是赋值，不是 copy
```

- 两个属性指向**同一个 `Parameter` 对象**（`data_ptr` 相同，`head.weight is tok_emb.weight → True`）
- 梯度会**累加**到同一块内存，`parameters()` 自动去重
- **省下 8,320 个参数**
- 合理性：输入时"这个字对应什么向量"和输出时"这个向量对应哪个字"本质上是同一张表的正反用

### 4. 三个必须有的工程细节

| 细节 | 为什么 |
|---|---|
| `nn.ModuleList` 而不是普通 list | 普通 list 不会 `.to(device)`，`.parameters()` 也找不到 → **模型能跑但永远不被训练** |
| `register_buffer(persistent=False)` | 跟着 `.to(device)` 走，但不进 `state_dict` |
| `self.mask[:T, :T]` 必须切片 | 生成时 T 会小于 `block_size` |

### 5. 数据管道：一个 batch 其实是 4096 个样本

```python
x = data[i     : i + block_size]        # (T,)
y = data[i + 1 : i + block_size + 1]    # 右移一位，每个位置的下一个字
```

**一个 `(64, 64)` 的 batch 含 64 × 64 = 4096 个独立训练样本**（每个位置都是一个预测任务）。

3000 步 × 4096 = **12.3M token** = 语料（100 万字符）的 **12 倍**。

### 6. 和 ResNet 训练脚本的三处不同

| | ResNet 05 | mini GPT 11 |
|---|---|---|
| 优化器 | Adam | **AdamW(betas=(0.9, 0.95))** — 0.95 让二阶矩衰减更快，对 transformer 的梯度尖峰更灵敏 |
| 学习率 | 纯余弦 | **warmup 100 步 + 余弦退到 10%** |
| 梯度 | 无裁剪 | **`clip_grad_norm_(1.0)`** — transformer 的 loss 尖峰比 CNN 多 |

### 7. 四层验证（光看 loss 不知道好坏）

| 层 | 检验什么 | 本次结果 |
|---|---|---|
| ① 四层基线 | 模型真的学到东西了吗 | 均匀 4.1744 → unigram 3.3092 → bigram 2.4819 → **本模型 1.7160** |
| ② 因果性 | 有没有偷看未来 | 前 5 个位置变化 **0.000000**，第 6 个 1.81 |
| ③ 不同温度 | 采样正常吗 | 0.5 重复、0.8 平衡、1.2 发散 |
| ④ 可复现性 | seed 管用吗 | 同 seed 两次生成**完全相同: True** |

**第 ① 层最重要**：光看 `val = 1.72` 你不知道这是好是坏。**必须和"笨基线"比。**

### 8. 温度、top_k：三个概念别混

| 概念 | 是什么 | 多少个值 |
|---|---|---|
| **logits** | 模型输出的原始分数 | **永远 65 个** |
| **softmax 概率** | 归一化后，和为 1 | **永远 65 个** |
| **top_k** | 生成时人为砍掉尾巴 | 通常留 40 个 |

**模型本身从来不筛。** `topk(3)` 只是我打印时取了前三名——完整分布一直是 65 维。

实测：位置 5（看到 `ROMEO:`）时，前 40 名占 **0.999625**，被砍掉的 25 个字符总共只占 **0.000375**。
→ **砍掉 25 个字符只丢 0.0375% 的概率质量。**

> **同一个模型的同一次前向，两个位置的分布形状天差地别**：
> 位置 0（只看到 `R`）最平的 top1 只有 0.15；位置 5（看到 `ROMEO:`）最尖的 `\n` 是 0.9915。
> **模型不只学"该输出什么"，还学"我有多确定"。**

### 9. 温度的本质：除法改变差值，exp 把差值变成倍数

```python
logits = logits[:, -1, :] / temperature    # 就这一行
```

`b` 与 `t` 原始差 `0.472`：

| 温度 | 差值变成 | 比值 | 实测验算 |
|---|---|---|---|
| 1.0 | 0.472 | `exp(0.472) = 1.60` | 0.0987 / 0.0615 = **1.60** ✓ |
| 0.3 | 0.472 / 0.3 = 1.573 | `exp(1.573) = 4.82` | 0.3180 / 0.0659 = **4.83** ✓ |

- 温度 → 0：退化成 argmax，陷入重复循环（0.5 时已出现 `and and`）
- 温度 = 1：模型本来的分布（诚实读数）
- 温度 → ∞：接近均匀，纯乱码

**和 top_k 的顺序不能反**：先温度改形状，后 top_k 砍尾巴。反了的话温度会把砍掉的部分重新"撑"回来。

### 10. steps vs epoch

| | ResNet | mini GPT |
|---|---|---|
| 单位 | epoch（看完 5 万张图 = 391 batch） | **step**（`opt.step()` 调用一次） |
| 数量 | 40 epoch = **15,640 步** | **3,000 步** |
| 样本量 | 200 万张图 | 1230 万 token |

**为什么语言模型用 step**：语料可以到几 TB，一个 epoch 几个月跑不完，这个领域约定俗成用 step。

### 11. 一个重要的判断：这不是过拟合

| | 值 | 含义 |
|---|---|---|
| train loss | 1.5533 | |
| val loss | 1.7271 | |
| **gap** | **0.17** | **很小** |

对比 ResNet：train 99.59% vs test 95.07%，gap 4.5 个点，那才是过拟合。

**gap 小的反义是"容量不够"**：模型还没吃满数据，加层数/加宽仍有收益。
nanoGPT（d=384, 6 层）能到 val 1.47，我们用了 1/8 算力到 1.73，在预期线上。

**提升顺序：先加层数，再加 d。**

### 3. §3 五节，一节一句话

| § | 原话要点 | 我的代码 |
|---|---|---|
| 3.1 | N=6 层，每层两个子层；输出是 `LayerNorm(x + Sublayer(x))` | `09` 的 `TransformerBlock`（N=4）|
| 3.2 | `softmax(QKᵀ/√d_k)V`；h=8，`d_k=d_v=d/h=64` | `07` / `08` |
| 3.3 | `max(0, xW₁+b₁)W₂+b₂`；d→2048→d；"等价于两个 1×1 卷积" | `09` 的 `FeedForward` |
| 3.4 | 两个词嵌入 + pre-softmax 共享权重；嵌入乘 `√d_model` | `11` 绑定 ✓，**乘 √d 没做** ✗ |
| 3.5 | 正弦位置编码；`PE_{pos+k}` 是 `PE_pos` 的线性函数 | `10`（我用了可学习版）|

**3.1 那句是全篇最容易忽略的一句。** `LayerNorm(x + Sublayer(x))` = **Post-LN**（LN 在残差加法**之后**）。

我写的是 Pre-LN：`x = x + self.attn(self.ln1(x))`（LN 在子层**之前**、残差**里面**）。

**这不是写错**：原论文 2017 是 Post-LN，GPT-2 之后全部改 Pre-LN，因为残差通路变成纯恒等、梯度直通、不需要 warmup。`09` 里 `norm_first` 一切换，**同样权重**下输出差 **1.4966**（输入 std 只有 0.9601）——证明这是两个完全不同的函数，不是实现细节。

### 4. Eq.1 逐字对照 + 脚注 1

论文：`Attention(Q,K,V) = softmax(QKᵀ/√d_k)V`

```python
scores = q @ k.transpose(-2, -1) / math.sqrt(self.d)
w = torch.softmax(scores, dim=-1)
out = w @ v
```

**脚注 1（原话）**：假设 q、k 分量独立、均值 0、方差 1，则点积 `q·k = Σ q_i k_i` 有**均值 0、方差 d_k**。

`demo_attention.py` 第 8 步实测：

| d | 实测 q·k 的 std | 理论 √d |
|---|---|---|
| 8 | 3.36 | 2.83 |
| 64 | 7.55 | 8.00 |
| 512 | 23.10 | 22.63 |

**这是独立复现了论文脚注，比"读懂了"硬。** 除以 √d_k 就是把这个 std 拉回 1；不缩放则 d=512 时最大权重已到 0.912，softmax 饱和 → 梯度 p(1−p)≈0。

论文还说 additive attention（Bahdanau）**理论复杂度相近但 dot-product 更快**，用的是 "can be implemented using highly optimized matrix multiplication code"。**它赢在能用 cuBLAS，不是赢在效果。**

### 5. 多头：`W^O` 的形状是全篇最容易抄错的

```
MultiHead(Q,K,V) = Concat(head₁, …, head_h) W^O
head_i = Attention(Q W_i^Q,  K W_i^K,  V W_i^V)
```

`W_i^Q, W_i^K ∈ R^{d_model×d_k}`，`W_i^V ∈ R^{d_model×d_v}`，**`W^O ∈ R^{h·d_v × d_model}`**。

**参数量 4d² 与 h 无关。** Table 3 的 (A) 组 `params` 列**四行全空白**——那就是证据。我实测 `h=1/2/4/8/16` 全是 **1088**。

论文动机原话：**"With a single attention head, averaging inhibits this."** 单头会把不同关系平均掉。

`W^O` 两个作用：①多头汇总（Concat 本身零交流）②把 `w@v` 从 **V 空间**翻译回**残差流空间**（**和 ResNet shortcut 上那个 1×1 投影同类**）。

### 7. 那个 √d_model 是干什么的

位置编码值域 [−1, 1]，嵌入初始化 `N(0, 0.02)`，**量级差一截**，相加时位置信息被淹没。

乘 √512≈22.6 后每分量 ~0.45，和 sin/cos 的 ~0.7 同量级，两路信号势均力敌。

**GPT-2 不用**：它连位置编码也是学出来的，两个都是学出来的 → 尺度自适应。**我这也是可学习 PE，所以不加也对。** 但要复现原配方就得加。

### 8. Table 1：三个 desiderata（先立标准，再逐条打分）

| 层类型 | 每层复杂度 | 最小串行步数 | 最长路径 |
|---|---|---|---|
| Self-Attention | O(n²·d) | **O(1)** | **O(1)** |
| Recurrent | O(n·d²) | O(n) | O(n) |
| Convolutional | O(k·n·d²) | O(1) | O(log_k n) |
| Self-Attention（受限）| O(r·n·d) | O(1) | O(n/r) |

**与 ResNet 同构的一招：**

| | ResNet | Transformer |
|---|---|---|
| 压哪个维度 | 深度（层 ↔ 层）| 序列（token ↔ token）|
| 原本路径长度 | L−l | j−i |
| 压缩后 | 1 | 1 |
| 实现 | `x + F(x)` | `Σ w_ij V_j` |
| 治什么病 | 深了训不动（退化）| 长了记不住（长程依赖）|
| 代价 | 参数 +173,824（1.58%）| 算力 O(n·d²) → O(n²·d) |

**连乘是万恶之源**：每层增益 0.9 → `0.9^100 ≈ 2.6e-5`；1.1 → `1.1^100 ≈ 13780`；只有乘 1 安全。

**"天下没有免费的直接通路"**：ResNet 用参数换，Transformer 用算力换。

### 9. §5 的十二个数字

```
4.5M 句对 (EN-DE)      BPE 共享词表 37000
36M 句 (EN-FR)         32000 word-piece
批 = 25000 源 + 25000 目标 token（按长度分桶）
硬件 8 × P100
base  0.4 s/step × 100K = 12 小时
big   1.0 s/step × 300K = 3.5 天
Adam  β₁=0.9  β₂=0.98  ε=1e-9
warmup 4000   dropout 0.1   label smoothing 0.1
```

**lr 公式**：`d_model^(-0.5) · min(step^(-0.5), step · warmup^(-1.5))`

- `step < 4000`：`min` 取第二项 → **线性升温**
- `step > 4000`：`min` 取第一项 → **1/√step 衰减**

**为什么必须 warmup**：Adam 第 1 步的更新量**恒等于 lr**——

```
m₁ = 0.1g,  v₁ = 0.001g²
偏差修正：m̂ = g,  v̂ = g²
更新量 = m̂/√v̂ = g/|g| = sign(g)      ← 与梯度大小无关！
```

参数随机初始化时方向是噪声，必须从 lr≈0 起步。**Pre-LN 不需要 warmup，Post-LN 需要**——这就是我用 `warmup=100` 而原文要 4000 的原因之一。

**③ big 不是"放大"，是"换配方"。** `P_drop` 0.1→**0.3**、步数 100K→**300K**、参数 ×3.3 换 dev BLEU **+0.6**，算力 ×3。base 才是效率故事，big 是刷榜用的。

**⑤ PPL 和 BLEU 的排序不一致。**

| 配置 | PPL | BLEU |
|---|---|---|
| d_model=1024 | **4.66**（第 2 好）| 26.0（第 3）|
| **ε_ls=0.0** | **4.67**（第 3 好）| **25.3（很低）** |
| d_ff=4096 | 4.75 | **26.2**（第 2）|
| **ε_ls=0.2** | **5.47（很差）** | **25.7（还不错）** |

**ε_ls 从 0.1 调到 0.2：PPL 恶化 0.55，BLEU 只掉 0.1。反过来 0.1→0.0：PPL 改善 0.25，BLEU 掉 0.5。**

论文原话：

> This hurts perplexity, as the model learns to be more unsure, but **improves accuracy and BLEU score**.

**PPL 衡量"模型对自己多自信"，BLEU 衡量"任务做得多好"，两者不等价。论文优化的是 BLEU。**

**以后看任何论文报一堆指标，第一件事问：「作者优化的是哪个？」**

### 12. 论文没说 / 说了但后来被推翻的四件事

**① "attention 让模型可解释"**
> individual attention heads clearly learn to perform different tasks

后来被打折：Voita et al. 2019 发现大量头可以剪掉不影响性能（冗余头），Jain & Wallace 2019 更直接——**attention 权重 ≠ 解释**。今天说"attention 图就是模型在想什么"是要被追问的。

**② "正弦编码 may allow extrapolation"**
> We chose the sinusoidal version because it **may** allow the model to extrapolate

**注意 `may`。** 论文自己都没证据。实际外推不好——我测的相似度**不单调**（距离 5 的 0.7361 > 距离 4 的 0.7288）就是证据之一。现在是 RoPE（让点积直接携带相对距离）和 ALiBi。

**③ O(n²) 被留作 future work，成为之后十年的主战场**
Longformer / BigBird（稀疏）、Linformer / Performer（低秩）、**FlashAttention**（数学不变，IO 优化）、**Mamba**（换掉通信层）。

**④ 论文没提梯度裁剪，但所有人都加**
transformer 的 loss 会突然尖峰（一个坏 batch 就能炸）。**这是实践知识，不在论文里。**

| 图 | 展示什么 | 论文声称 |
|---|---|---|
| **Fig 3** | **长距离依赖**：动词 "making" 跨越多个词去够 "more difficult" | 头能追踪"making...more difficult"这个动宾结构 |
| **Fig 4** | **指代消解**：代词 "its" —— 一个头指向 "Law"，另一个头指向 "application" | 不同的头在处理同一个代词的不同候选 |
| **Fig 5** | **局部/句法**：有的头只盯着相邻的下一个词 | 头部行为与句子结构相关 |

**核心声称**：`individual attention heads clearly learn to perform different tasks`。

**但这是定性观察，不是定量证据。** 三张图、一层、一个句子——没有统计，没有消融。**后来被剪枝实验打了折。**

**面试怎么用**：别说"attention 可解释"。说"**论文用附录 Fig 3–5 声称不同头学到不同功能（长距离依赖、指代消解、局部结构），但这是定性观察；后续 Voita 2019 的剪枝实验表明大部分头是冗余的，Jain & Wallace 2019 也指出 attention 权重不等于解释。**"

**一句话把论文说了什么、局限在哪、后来怎么发展全带上。**

## 第 13 课 · ViT 与样本效率（W2）

> 论文：Dosovitskiy et al., *An Image is Worth 16×16 Words: Transformers for Image Recognition at Scale*, ICLR 2021（arXiv:2010.11929）
> 代码：`practice\12_vit_cifar.py`　实验：#23–#26（见 `EXPERIMENTS.md`）

### 1. 一句话结论

**ViT 与 ResNet-18 在 CIFAR-10 上"记忆训练集"的能力完全相同（train 98.5% vs 98.5%），但泛化差 16.24 点（77.27% vs 93.51%）。**

### 2. 你其实早就写过 ViT 了

ViT 论文的 Eq.2 / Eq.3：

```
z'_ℓ = MSA(LN(z_{ℓ-1})) + z_{ℓ-1}
z_ℓ  = MLP(LN(z'_ℓ))   + z'_ℓ
```

对照 `09_transformer_block.py` 的 `forward`：

```python
x = x + self.attn(self.ln1(x))
x = x + self.ffn(self.ln2(x))
```

**逐字一致。** 论文原文 "Layernorm (LN) is applied **before** every block" —— 是 Pre-LN，不是 BERT 的 Post-LN；MLP 是 "two layers with a GELU non-linearity"，就是 `FeedForward`。

> 这是读论文最爽的一次体验：**你已经知道 80% 了，论文只是换了个输入。**

### 3. ViT 唯一的新东西：式 (1)

```
z₀ = [ x_class ; x_p¹E ; x_p²E ; … ; x_p^N E ] + E_pos
E ∈ R^{(P²·C)×D},   E_pos ∈ R^{(N+1)×D}
```

三件事，全是形状操作：

| 步骤 | 做什么 | 代码 |
|---|---|---|
| 切块 | 把 H×W×C 的图切成 N 个 P×P×C 的块 | `x.unfold(2,P,P).unfold(3,P,P)` |
| 展平+投影 | 每个块拉平后过**一个线性层** | `nn.Linear(P*P*C, d)` |
| 加 CLS + 位置 | 前面插一个可学习的 token，全体加位置编码 | `nn.Parameter` + 广播相加 |

**注意 `E` 是 `nn.Linear`，不是卷积。** 但 `Conv2d(3, d, kernel_size=P, stride=P)` 在 kernel == stride 时每个输出位置只看一个块，**和逐块线性投影数学等价**（官方实现就用 Conv2d，快）。

### 4. Token 数怎么算

```
N = (H/P) × (W/P)
```

| 输入 | P | N | +CLS | 用于 |
|---|---|---|---|---|
| 224×224 | 16 | 14×14=196 | **197** | ViT-B/16、ViT-L/16（论文） |
| 224×224 | 32 | 7×7=49 | 50 | ViT-B/32 |
| 224×224 | 14 | 16×16=256 | 257 | ViT-H/14 |
| **32×32** | **4** | 8×8=64 | **65** | **本次实验** |
| 32×32 | 8 | 4×4=16 | 17 | 太少，试过 |

**为什么我们不用 P=16**：32×32 切成 16×16 只有 **4** 个 token，注意力矩阵是 4×4，序列建模无从谈起。**P 翻倍，token 数降到 1/4，注意力计算量降到 1/16**（O(N²)）。

### 5. 和语言模型只差两行

```python
# 11_mini_gpt.py
x = self.tok_emb(idx) + self.pos_emb(arange(T))

# 12_vit_cifar.py
x = self.patch_embed(x)                        # ← 换这里
x = torch.cat([self.cls.expand(B,-1,-1), x], 1)  # ← 加 CLS
x = self.drop(x + self.pos)

for blk in self.blocks:
    x = blk(x)      # ← 不传 attn_mask：图像没有"未来"
```

**`attn_mask=None` 是全篇最关键的一处调用差异。** 语言模型必须遮住未来（因果），图像没有未来——一只猫的左上角和右下角是同时存在的。

### 6. 五组实验的数字

| # | 配置 | 参数 | epochs | train | test | gap | 诊断 |
|---|---|---|---|---|---|---|---|
| — | ResNet-18（参照） | 11.17M | 40 | 98.45 | **93.51** | 4.94 | 过拟合但泛化好 |
| 23 | ViT d192 L4 | 1.80M | 40 | 71.62 | 69.79 | **1.83** | **欠拟合** |
| 24 | ViT d384 L6 | 10.70M | 40 | 57.86 | 57.61 | **0.25** | **欠拟合 + 不稳定** |
| 25 | 同 #24 + warmup 5 | 10.70M | 40 | 67.23 | 65.92 | 1.31 | 欠拟合（改善 +8.31）|
| 26 | ViT d192 L4 | 1.80M | 200 | **98.51** | **77.27** | **21.24** | **严重过拟合** |

### 7. 病反过来了

同一个模型、同一套数据管道，只是训练预算不同：

- 40 轮：train **71.62%** —— 连训练集都没拟合上 → **欠拟合**
- 200 轮：train **98.51%** —— 记住了 → **过拟合**，test 卡在 77.27%

test 只涨了 **+7.48**，train 涨了 **+26.89**。多出来的 160 轮几乎全用来记训练集了。

### 8. 决定性对比：在 train 准确率相同的点上比 test

| 模型 | 参数 | train | test | gap |
|---|---|---|---|---|
| ResNet-18 | 11.17M | **98.45%** | **93.51%** | 4.94 |
| ViT | **1.80M** | **98.51%** | **77.27%** | **21.24** |
| 差值 | −83% | +0.06 | **−16.24** | **×4.3** |

**"记忆训练集"打平，"用起来"差 16.24 点。**

而且注意这个反差：**ViT 参数只有 ResNet 的 1/6，gap 却是它的 4.3 倍。**

> 这不是"容量大所以过拟合"，而是**没有局部性先验，所以更容易记住无关细节**。
> 卷积的"只看邻域"是一个极强的约束，它让模型**不容易**学到"这张图右下角有个奇怪纹理"这种只在训练集里成立的捷径。

### 9. warmup 为什么能救回 8.31 点

联系第 12 课算过的那件事：**Adam 第一步 `m̂/√v̂ = g/|g| = sign(g)`，更新量恒等于 lr，与梯度大小无关。**

随机初始化时，梯度方向基本是噪声，但步子已经是满的。模型越大，这一步推得越远：

| | 无 warmup（#24） | 有 warmup（#25） |
|---|---|---|
| ep1 train | 26.67% | **38.90%**（+12.23）|
| 最大单轮跌幅 | **2.89** | **1.04** |
| 累计跌幅 | **7.06** | **3.03** |
| ep40 test | 57.61% | **65.92%**（+8.31）|

**下坠的次数都是 6/39——warmup 不是让曲线变单调，而是让每次跌得浅。**

warmup 之后 gap 从 0.25 涨到 1.31，**这一步 gap 变大是好事**：说明模型终于开始拟合训练集了。

> 这也解释了为什么"Post-LN 必须配 warmup 而 Pre-LN 可以省"——Pre-LN 让梯度主干是恒等的，早期震荡传不深；但**参数更新方向仍然是噪声驱动的**，所以大模型还是要 warmup。

### 10. 判读规则的修正（重要）

之前说过"gap 大 = 过拟合"。这句话**有前提**：train 本身要够高。

> **正确的判读：先看 train 的绝对值，再看 gap。**

| 情况 | train | test | gap | 真相 |
|---|---|---|---|---|
| ResNet-18 | 98.45 | 93.51 | 4.94 | 真过拟合（会背，但泛化还行）|
| ViT 40 轮 | 71.62 | 69.79 | **1.83** | **两条线一起低 = 欠拟合** |
| ViT 200 轮 | 98.51 | 77.27 | **21.24** | 真过拟合（会背，但不会用）|

**同一个 gap 指标，在 1.83 和 21.24 两个值上都可能是"病"，但病完全不同。**

### 11. 论文说了什么 vs 我们验证了什么

论文 §1 的诚实承认：

> "trained on mid-sized datasets such as ImageNet ... yield **modest accuracies of a few percentage points below ResNets**"（ImageNet 1.28M 张）

原因："Transformers lack ... **translation equivariance and locality**"。
题眼：**"large scale training trumps inductive bias"**。

**我们的数字比"几个点"大得多（16.24），因为数据少 25 倍**（CIFAR 5 万 vs ImageNet 128 万），而且我们**没有任何强增强**。

**能说的**：

> 在 CIFAR-10、同等数据管道、同等轮数下，参数匹配的 ViT 泛化能力比 ResNet-18 低 16.24 点且过拟合更严重（gap 21.24 vs 4.94），尽管两者训练集准确率相同。这与"缺少 locality / translation equivariance 等归纳偏置导致样本效率低"的论断一致。

**不能说的**：

> 不能说"ViT 不适合小数据"。因为 **16.24 点里有多少是"配方"、多少是"先验"，这个实验没分开**——我们完全没用论文 / DeiT 的 RandAugment、Mixup、CutMix、stochastic depth、label smoothing。

### 12. DeiT 的存在就说明这一点

DeiT（Touvron et al., 2021, arXiv:2012.12877）摘要原话：

> "visual transformers are **pre-trained with hundreds of millions of images using an expensive infrastructure**, thereby limiting their adoption. In this work, we produce a competitive convolution-free transformer by **training on Imagenet only**. We train them on a single computer in less than 3 days. Our reference vision transformer (86M parameters) achieves **top-1 accuracy of 83.1%** ... with **no external data**."

**ViT 在 ImageNet-1k 上从零开始训练是可以打赢 CNN 的，但需要一整本配方**：

| 项 | ViT 原论文（JFT 预训练）| DeiT（ImageNet-1k 从头）|
|---|---|---|
| 轮数 | 7–14 epochs on 300M | **300 epochs** |
| 增强 | crop | **RandAugment + Mixup + CutMix + RandomErasing** |
| 正则 | dropout 0.1 | **+ stochastic depth、label smoothing 0.1** |
| warmup | — | **5 epochs** |
| 结果 | 88.55%（ViT-H/14）| **83.1%（ViT-B，单机 3 天）** |

**DeiT 这篇论文的全部意义就是：naive 训练 ViT 会失败，这是配方问题。** P6（ViT + CutMix 200 轮）就是去验证我们这条差距里配方占多少——结果见下一节。

### 13. P6 跑完：CutMix 填平了 36.1%

**实验 #27**：`12_vit_cifar.py --epochs 200 --mix cutmix --mix-alpha 1.0 --mix-prob 0.5`，其余一字不改。62 分钟。

| | #26 无 CutMix | #27 有 CutMix | Δ |
|---|---|---|---|
| train | 98.51 | **95.63** | −2.88 |
| test | 77.27 | **83.14** | **+5.86** |
| gap | 21.24 | **12.38** | −8.86（−41.7%）|

```
原始差距（#26 vs ResNet-18 的 93.51）  16.24 点
CutMix 拿回                            5.86 点  →  36.1%
剩余                                  10.38 点
```

**36.1% 这个数让我必须收回之前的话**：我原先说"16.24 点主要是归纳偏置"，**说得太满**。配方没配齐确实吃掉了一大块。但反过来，一个 CutMix 也明显填不平剩下的 10.38 点。

三个读数，每个说明一件事：

1. **前 40 轮反而更慢（66.32 vs 68.46），最后反而更高（83.14 vs 77.27）**
   两个都是 `T_max=200`，所以前 40 轮可比。混合标签让小模型前期难拟合，但收敛到更高的地方。
   **别在前 20 轮就下结论**——这是增强实验的通用规律。

2. **gap 12.38 仍然是 ResNet 的 2.5 倍**（4.94）
   而且是"ViT 的 train 更低（95.63 vs 98.45）、gap 却大得多"——连"记得更牢"都不成立。
   **这排除了"容量/拟合能力"的解释，留下"记住的东西不对（无关细节）"这一条。**

3. **模型已饱和**：ep180→ep200 只涨 0.32 点，lr 已趋 0。再加轮数没用。

**结论措辞（重要，别说过头）**：

✅ 能说：
> 同等数据管道下，参数匹配的 ViT 比 ResNet-18 差 16.24 点；补上 CutMix 后差距压缩到 10.38 点（填平 36.1%），但 ViT 的泛化差距仍是 ResNet 的 2.5 倍，且训练集准确率反而更低。方向与 ViT 论文「缺 locality 与 translation equivariance」的论点一致。

❌ 不能说：
> "证明了 ViT 因为缺归纳偏置所以差 10 点。"

因为配方只补了 **1/5**（还缺 warmup、RandAugment、Mixup、stochastic depth、label smoothing），轮数 200 vs DeiT 300，而且 CIFAR 的 64 个 token 让长程优势根本发挥不出来。**这是"方向一致"，不是"因果证明"。**

### 14. 局限

- **只有 1 个 seed**
- **#26 的前 40 轮 ≠ #23**：余弦调度 `T_max` 跟着 `epochs` 走，#26 在 ep40 时 lr 还有 0.00095，#23 已降到 0。所以"前 40 轮均值 68.46 vs 69.26"的 0.8 点差异来自 **lr 调度长度**，不是模型
- **配方只补了 CutMix 一个**：P6 之后"剩下 10.38 点里还有多少是配方"仍未分开
- **没做数据量梯度**（CIFAR-10 → CIFAR-100 → ImageNet 子集），而论文最核心的证据正是那条曲线
- **没做种子复现**，16.24 点远大于噪声底（0.06），结论稳，但 warmup 的 +8.31 只跑了一次

## 附录 · 慢下载怎么破

这条是通用技能，以后下数据集、下预训练权重都会用到。

**症状**：单线程下载只有 10–40 KB/s，170 MB 要几个小时。

**诊断顺序**：

1. **先看单连接速度上限**。很多学术站点（如 `cs.toronto.edu`）单条 TCP 连接被限速在 40 KB/s 左右，但**整体带宽不差**。
2. **确认服务器支持分段**：请求头里看 `Accept-Ranges: bytes`。
3. **开多线程分段下载**，每块用 `Range` 请求独立下载。
4. **并发数从 8 开始，别一上来就 16**。实测 16 线程全部卡死（0 进展），8 线程反而跑到 0.21 MB/s，5 倍于单线程。

**实测对比**（CIFAR-10，170 MB）：

| 方式 | 速度 | 结果 |
|---|---|---|
| 直连单线程 | 10 KB/s | 4–5 小时，放弃 |
| 代理 + 单线程 | 40 KB/s | 70 分钟 |
| 代理 + 16 线程 | — | **全部卡死** |
| 代理 + 8 线程分块 | 0.21 MB/s | **13 分钟完成** |

**另一条经验**：`TUN 模式 ≠ 全网走节点`。TUN 只负责把流量截给代理软件，走直连还是走节点仍由**分流规则**决定——所以开了 TUN 也可能对某些站点走直连。

**最后**：下完一定要验 MD5。断点续传、多线程拼接都可能出问题，校验和是唯一可信的证据。
